# 400 个遗忘模型的批量生成方案：200 个 LoRA、200 个全参数

更新：2026-11-03，纽约时间。当前正式批量生成开关关闭，本文更新规划与验收要求。机器可读分配为 [任务配额 JSON](unlearning_400_allocation.plan.json)，[English version](UNLEARNING_400_BALANCED_PLAN_EN.md)。本文件取代此前三来源及五算法的正式配额；此前数量分别保存在 [10 月 30 日配额](unlearning_400_allocation.20261030.historical.json) 和 [11 月 1 日配额](unlearning_400_allocation.20261101.historical.json)。

## 1. 最终要交付什么

交付 **400 个通过效果检查的遗忘模型样本**：200 个在遗忘阶段使用 LoRA，200 个在遗忘阶段更新整个模型。另准备最多 400 个匹配的正常继续训练模型，用作检测器的无遗忘对照。因此，含全部对照时最多有 800 个模型样本。两个前置学习起点、开发小试、失败尝试和中间保存点单独计数。

这次的 50:50 指的是**遗忘阶段**。人物和文章分别先训练一个完整的 Llama-2-7B-Chat 学习起点；LoRA 和全参数两组均从相应的同一份学习后权重开始。LoRA 组冻结这份权重，只训练新增的小矩阵；全参数组允许原模型的全部参数更新。保存为完整权重文件或保存为适配器文件，是另外一项存储设置。

正式方法选 NPO、SimNPO、GradDiff、UNDIAL，各 100 个：每种方法 50 个 LoRA、50 个全参数，且各有 50 个人物任务、50 个文章任务。RMU 原始实现主要修改指定层，因此放入独立的局部更新扩展小试。当前五方法小试的结果与配置继续保留；RMU 的局部更新样本单独记录。

## 2. 数据是什么，各有多少

使用已经下载并核对过的公开文本、问题和答案。人物来自 [alex-karev/biographies](https://huggingface.co/datasets/alex-karev/biographies)，固定 revision 为 `f724ba85ffd01f046626c193c1a99385a7a60038`；文章来自 [SQuAD 1.1](https://rajpurkar.github.io/SQuAD-explorer/)。原始文件版本、字节数与 SHA256 已存入 `official_knowledge/source-manifest.json`。人物发布页标注 Apache-2.0；SQuAD 标注 CC BY-SA 4.0，材料与衍生清单保留对应署名及许可。

| 统计项目 | 人物材料 | 文章材料 |
|---|---:|---:|
| 清洗后结构合格的公开内容单元 | 993 人 | 476 篇文章 |
| 已进入当前小试学习池，排除出正式目标 | 120 人 | 40 篇文章 |
| 小试池之外的候选 | 873 人 | 436 篇文章 |

| 事先学入起点的备用目标 | 50 人 | 50 篇文章 |
| 专门用于保留训练和正常对照的内容 | 100 人 | 50 篇文章 |
| 正式前置学习池合计 | **350 人** | **300 篇文章** |
| 选完上述学习池后仍未使用 | 523 人 | 136 篇文章 |

每个正式模型遗忘**一位不同人物或一篇不同文章**。正式 400 项之间删除目标不重复；更换算法、训练方式、种子或保存时刻均不产生新的内容目标。开发小试可让不同方法处理相同的四个目标，用于比较方法；这些小试不计入 400。

人物每人有六项属性，每项有二十条已发布训练表达。350 人共有 **2,100 项人物属性事实、42,000 条训练句子**。按当前 120 人实读的 token 均值外推，一轮约 75 万 tokens，五轮约 375 万 tokens；正式选人后重新精确分词计数。

文章学习提供原始正文及每篇 40 组已发布问答，另外每篇保留 20 组不同问题作闭卷检查。300 篇共有 **12,000 组训练问答、6,000 组检查问题**。按当前 40 篇小试均值，正文切块约 13,100 条，总训练记录约 25,100 条，一轮约 304 万 tokens，五轮约 1,520 万 tokens。这些正文与 token 数是预算值，文章清单冻结后给出实数。

清洗沿用已核查的规则：人物姓名损坏项剔除；训练句首与检查提示去重；文章按正文重复、指代不明、答案泄露和同段同答案的问题组清理；长正文按分词长度切块；每条保留来源 ID。闭卷检查只提供人物句首，或文章标题与问题。这里使用原发布材料，不调用语言模型编造新事实或新问答。

## 4. LoRA 与全参数分别怎样训练

| 设置 | 200 个 LoRA 遗忘模型 | 200 个全参数遗忘模型 |
|---|---|---|
| 初始权重 | 对应来源已验收的完整学习起点 | 同一份完整学习起点 |
| 可训练参数 | 只训练 LoRA 小矩阵；原模型权重冻结 | 原模型全部参数可更新 |
| 初始 LoRA 配置 | rank 16、alpha 32、dropout 0.05、bias `none`；注意力 q/k/v/o 和 MLP gate/up/down 七类线性矩阵 | 无适配器 |
| 可训练参数规模 | 约 4,000 万，约占完整模型 0.59% | 约 67.4 亿 |
| 数值精度 | BF16 原始权重；适配器存储 dtype 单独记录 | BF16 原始权重；优化器状态按有效配置记录 |
| 初始学习率 | `1e-4`，在开发目标上核定后冻结 | NPO、SimNPO、GradDiff 为 `1e-5`；UNDIAL 为 `1e-4` |
| 初始训练预算 | 最多 10 轮、有效批量 32 | 最多 10 轮、有效批量 32 |
| 遗忘材料 | 该人物的全部 120 句，或该文章的全部训练正文块及 40 组问答 | 相同的任务定义；正式目标内容各不相同 |
| 保留材料 | 同来源的专用保留池，按本任务预算配对 | 同来源的专用保留池，按本任务预算配对 |
| 算法实现 | 官方损失与训练器，加薄的 Hugging Face PEFT 模型接入 | 官方损失与训练器 |

LoRA 的 rank、学习率和目标矩阵均为待小试核定的初始方案。对照使用相同的更新方式、rank、学习率、更新预算和相当的 token 预算。[PEFT 官方文档](https://huggingface.co/docs/peft/main/en/conceptual_guides/lora)说明了冻结原权重、低秩更新与合并方式。当前固定版本的 OpenUnlearning 接入 LoRA 还需要实现和验证，现有全参数流程的完成情况单独记录。

| 方法 | 遗忘时具体做什么 | 固定参考模型的使用 |
|---|---|---|
| NPO | 降低目标内容的相对偏好，并维持保留材料表现 | 使用同一学习起点的固定副本 |
| SimNPO | 按长度归一化的目标损失进行遗忘，并维持保留材料表现 | 当前 NLL 保留配置不需要 NPO 式参考副本 |
| GradDiff | 提高遗忘材料的预测损失，同时降低保留材料的预测损失 | 当前 NLL 保留配置不需要参考副本 |
| UNDIAL | 让学生学习经过调整、降低目标 token 倾向的教师输出 | 使用同一学习起点的固定教师 |

LoRA 接入时，NPO／UNDIAL 的固定参考必须加载**学习起点**，训练副本才挂载可训练适配器。冻结参考的参数、适配器白名单和梯度范围都做检查。NPO、SimNPO、UNDIAL 的方法专属系数在开发目标上分别冻结，完整 YAML 写明具体值。当前全参小试的系数只作为初始配置，LoRA 分支重新核定。

单卡优先给不需参考副本的 LoRA 任务；NPO／UNDIAL 如需双卡或参考模型 CPU offload，先测实际峰值，再分配资源。全参数任务优先测试参数留在 GPU、优化器卸载到 CPU 的配置，保留当前双卸载配置作可恢复基线；运行配置由实际保存、恢复和内存测试确定。

## 6. 先小试，再放大

现有小试学习池为 120 人和 40 篇文章，四个不同删除目标分别用于开发和确认。扩充为四种正式算法 × 两种来源 × 两种更新方式 × 两个目标，共 **32 次遗忘小试**；相同四个目标供方法比较。按四个目标、两种更新方式和两种学习率预算准备最多 **16 个不同的正常对照**。当前四个 RMU 原权重更新配置小试保留作局部更新扩展，数量另列。

每种方法在开发目标上选择参数，再用未参与选参的确认目标复核。下面的阈值为本项目小试的初始验收线，正式配方由小试冻结，并对两种更新方式使用同一标准。

| 检查项目 | 准入条件 |
|---|---|
| 起点已学会 | 目标知识正确率至少 80%，相对原始 Chat 提高至少 20 个百分点；保留知识正确率至少 80% |
| 目标遗忘 | 原先会答的目标问题中，遗忘后仍会答的比例不超过 30% |
| 保留知识 | 原先会答的保留问题中，遗忘后仍会答的比例至少 95% |
| 一般能力 | MMLU validation 准确率下降不超过 3 个百分点；完整 test 作为最终复核 |
| 正常继续训练对照 | 目标知识和保留知识分别保留至少 95% 的原先正确项 |
| 结果材料 | 保存逐题回答、知识正确率、答案 EM／token F1、MMLU 准确率及前后变化 |

检测器训练完成后，另外报告 TPR、TNR、Accuracy、Precision、Recall、F1、AUROC，并按数据来源、算法和更新方式拆表。每个 25 项格子必须完成 25 个合格且内容不同的目标，失败用已学习的备用内容替换。失败尝试和重复种子不补名额。

## 7. 给 AC／AcT 保存什么

全部合格模型及正常对照均使用同一论文式短输入协议 `paper-t2`：每个模型最终保存 64 份活动记录，分别读取第 1、16、32 层，每层每份为 4,096 个数值。T=2 属于检测器探测输入的协议；语言模型学习和遗忘仍使用各自完整训练文本。

LoRA 模型按固定合并流程得到普通 Llama 模块视图，再提取与全参模型同形的内部活动；先验证合并前后的输出一致性与允许的数值误差。保留原适配器、父模型哈希和合并配置。每项同时保存真实探测文本、层名、模型 ID、数据目标、更新方式、训练配置、逐题评估、活动哈希和父模型哈希。

按 FP16／BF16 每数值 2 字节计算，活动净数据为：`64 × 3 × 4096 × 2 = 1,572,864 字节`，约 **1.5 MiB／模型**。400 个遗忘模型约 600 MiB，含 400 个对照时约 **1.17 GiB**；文件头、JSON 和文本日志另外预算。64 份记录已经是提取后的最终数量。

## 9. 预计需要多久

**已有实测**：当前人物小试的一个成功更新区间，1,125 次更新用时约 8 小时 3 分，均值约 25.8 秒／次；较早区间约 33–35 秒／次。该任务在 2.5 轮的保存阶段被自身内存保护停止，尚无合格的最终学习模型。下面的人物全参预算基于更新吞吐；保存、恢复和 LoRA 速度仍需实测。

| 阶段 | 任务量 | GPU 工时预算 | 依据 |
|---|---|---:|---|
| 补齐 LoRA／全参配方小试 | 32 个遗忘小试及最多 16 个对照 | 20–50 | 小试规模预算；LoRA 尚未测速 |
| 两个正式前置学习起点 | 人物约 6,565 次更新；文章约 3,925 次更新 | 140–280 | 人物按已测速度外推；文章按较长输入与更多梯度累积预留 |
| 正式全参遗忘 | 100 个人物、100 个文章任务 | 80–240 | 每任务最多 10 轮，文章任务长度逐项计算 |
| 正式 LoRA 遗忘 | 100 个人物、100 个文章任务 | 20–80 | 待小试标定的预算假设 |
| 匹配正常对照 | 最多 400 个任务 | 60–180 | 按更新方式分别预算 |

GPU 工时为实际占用的 GPU 数量乘运行小时；某个 NPO／UNDIAL 任务若独占两卡一小时，记两 GPU 小时。单卡连续获得资源时约 **25–65 天**。如果实测能维持两个等效单卡任务并行，理论为 **13–33 天**；参考副本用卡、CPU 内存和 GPU 等待会影响实际日历时间。

当前约 251 GiB 主机内存，现有全参任务上限为 144 GiB，因此当前配置同时运行一个全参任务。其他空闲卡可在内存预算允许时用于 LoRA 或评估。正式排程依据各阶段实际峰值；每一至两天更新吞吐记录，并在首批 16 个合格模型完成后重算剩余预算。任务结束或真实进展变化时更新状态文件，不创建新的定时自动任务。

## 10. 批量代码要具备的能力及执行顺序

沿用 OpenUnlearning 的数据类、模型模板、训练器和损失。本项目补配置与薄接入层：任务清单、PEFT 加载、固定参考、逐任务资源限制、恢复或重跑、效果验收和现有 BackdoorID 活动提取。任务键至少包含来源、删除目标、算法、更新方式和配方版本。

按 `prepared → learned_parent_verified → trained → evaluated → activation_verified → accepted` 保存状态，保留失败原因。重复运行先核对已有文件的内容哈希，已完成的工作继续复用。短任务中断只重跑当前任务；长学习任务读取通过检查的完整断点。
